# Phase 3 — Boundary slice: flippable 2-D env + CPU micro-LeWM

Status: **built, trained, measured**. This document is the protocol and the
empirical record for the physics boundary that phases 4–5 consume (digest
clustering, ratchet overlay, gravity-flip acceptance). There is no executor
coupling in this slice.

## 1. Environment specification

Own world; no Two-Room, no external dataset (the LeWM paper flags Two-Room as
degenerate for SIGReg, and this slice exists to study the flip, not to
reproduce the paper).

| Property | Value |
| --- | --- |
| Frame | `(96, 96, 3)` `uint8`, values `[0, 255]`; channels-last from `reset`/`step` |
| Coordinates | normalized `[0,1]²`, `x` right, `y` up; renderer uses `row = (1-y)*(H-1)` |
| Bodies | agent disc `r = 0.075`, object disc `r = 0.060`; no body-body collision |
| Walls | closed box; reflective, restitution `0.90` |
| Integration | semi-implicit Euler, `dt = 0.1`; speed clipped to `max_speed = 2.0` |
| Gravity | magnitude `4.0` world-units/s²; sign `+1` = down (`-y`), `-1` = up (`+y`) |
| Agent control | thrust `6.0` world-units/s², applied as a velocity impulse `thrust*dt` |
| Actions | 5 discrete: `0 noop, 1 left, 2 right, 3 down, 4 up` |
| Episode state | `tick`, `gravity`, `gravity_sign`, `signed_gravity`, `gravity_flips`, agent/object positions and velocities, radii, `last_action`, `episode_seed` |
| Determinism | `float64` numpy; `reset(seed)` draws positions/velocities from `default_rng(seed)`; `step` has no randomness |
| Bounds | positions in `[radius, 1-radius]` per axis; velocities `≤ max_speed`; frames `uint8` |

The **gravity flip is a dynamics change, not a visual trick**:
`flip_gravity()` only negates the acceleration sign. The renderer never
receives the sign, tick, action, or seed. Two worlds in the same physical
state render byte-identical frames under opposite signs (asserted in
`tests/test_physics_env.py::test_flip_does_not_change_rendering_of_a_fixed_state`);
trajectories diverge only after the next `step` because the acceleration law
changed. With zero velocity, one no-op step moves the agent `0.04` world-units
down at `+1` and `0.04` up at `-1` (asserted).

Static pixels: dark background, 8-pixel grid, wall border. The two discs are
cyan (agent) and orange (object) with soft 1.35-pixel anti-aliased edges.
Nothing in the frame encodes the gravity sign.

Deliberate simplifications (honesty notes 9–10): no body-body collision, no
friction, no action on the object, no episode termination. The world is a
closed conservative box except for wall restitution and the speed cap.

## 2. Data protocol

Rollouts are generated by stepping `PhysicsEnv`; actions are drawn per
episode from a `numpy` generator derived from the dataset seed, independent
of the reset seed (so action and initial-state streams are decoupled and both
reproducible).

| Split | Episodes | Horizon | Gravity | Purpose |
| --- | --- | --- | --- | --- |
| Train | 64 | 24 | `+1` whole episode | fitting set (in-distribution) |
| Validation | 8 | 24 | `+1` | model selection / final window loss |
| Eval normal | 16 | 24 | `+1` whole episode | in-distribution surprise |
| Eval mid-flip | 16 | 24 | `+1`, flipped at step 8 | phase-5 acceptance event |
| Eval whole-flip | 16 | 24 | `-1` from reset | never-seen dynamics law |

The three evaluation sets **use the same reset seeds and action streams**; the
normal and mid-flip twins are identical for steps `0..7`, so any difference
after step 8 is caused by the gravity flip alone. 384 transitions per
regime.

Fitting is deliberately normal-gravity-only: if the model were trained on
both signs, there would be no in-distribution vs flipped split to measure.
`--train-gravity mixed` exists as a control but was not part of the reported
run (honesty note 12).

## 3. Micro-LeWM

| Component | Configuration | Trainable params |
| --- | --- | --- |
| Encoder | 3× strided CNN `3→16→32→32` (k5/k3/k3, stride 2), GELU, linear `4608→64` | 310,080 |
| Predictor | action embedding `5→8`, 2-layer GRU `64+8→128`, residual MLP head `200→128→64` | 210,920 |
| SIGReg | 17 knots on `[0,3]`, 256 random unit projections, λ = 0.09 | 0 (buffers only) |
| **Total** | ~0.52 M parameters (budget ≲ 2 M) | **521,000** |

Latent `z_t` is 64-dimensional. The predictor is causal: it runs a GRU over
`[z_t, embed(a_t)]` and outputs `z_{t+1}` for every transition; the head's
last layer is zero-initialised, so the model starts as the identity predictor
and learns a residual dynamics. The loss is the LeWM two-loss form:

```
loss = MSE(z_hat_{t+1}, z_{t+1}) + 0.09 * SIGReg(z)
```

SIGReg is the reference Epps–Pulley form: empirical characteristic function of
random projections compared with the standard-normal one at 17 frequencies,
weighted by the reference window, multiplied by the batch count and averaged.
For scale: SIGReg of exactly-collapsed latents at this configuration is
`9.649`; of iid `N(0,1)` latents it is `≈1.105` (measured, seed 0). Training
started at `9.653` and ended at `1.457` (honesty note 6).

**Binding ruling — frozen encoder.** The encoder is fit jointly with the
predictor (LeWM-style), then `fit(..., freeze_after=True)` calls
`freeze_encoder()`: `requires_grad=False` on every encoder parameter, encoder
forced to `eval()`, and `train()` overridden so the encoder stays in eval mode.
`encoder_parameters()` and `predictor_parameters()` are disjoint lists;
`predictor_optimizer()` yields a predictor-only AdamW. A backward pass after
freezing gives `None` gradients for every encoder parameter and gradients for
predictor parameters (tested). The checkpoint records the frozen flag; a clean
process loading `.work/forge/checkpoint.pt` reports `encoder_frozen=True`.

## 4. Training protocol

| Item | Value |
| --- | --- |
| Seed | 0 (env seed streams `seed+11/12/21/31`; torch and window RNGs seeded from it) |
| Windows | contiguous `seq_len = 12` transitions (13 frames) |
| Batch | 24 windows |
| Optimizer | AdamW, lr `2e-3`, weight decay `1e-4`, grad clip `1.0` |
| Steps | 1200 (28,800 window samples) |
| Threads | 8 (`torch.set_num_threads(8)`) |
| Encoder after fit | frozen + eval |

The CLI evaluates a fixed validation window every 100 steps and reports
`MSE` only (no SIGReg) for that window.

## 5. Measurements

### 5.1 Loss curve

| Series | First | Final | Min (step) | Mean of last 10% |
| --- | --- | --- | --- | --- |
| Total loss | 0.8688 | 0.1520 | 0.1269 (1009) | 0.1601 |
| Prediction MSE | 1.55e-6 | 0.02085 | — | 0.02083 |
| SIGReg | 9.653 | 1.457 | 1.208 (1130) | 1.547 |

The prediction MSE necessarily starts at ~0 because the zero-initialised head
is the identity predictor and consecutive latents are initially similar; as
SIGReg spreads the latents the absolute prediction error becomes meaningful.
The non-trivial evidence is that the model beats the identity baseline by a
wide margin after fitting.

Validation window (fixed 24×13 frames, seeded): model MSE `0.04798` vs
identity MSE `0.22893` — the model is **4.77× lower** than predicting
`z_{t+1} := z_t`.

Validation evaluation curve (prediction MSE): `1: 0.0008, 100: 0.0775,
200: 0.0419, 300: 0.0499, 400: 0.0435, 500: 0.0515, 600: 0.0671, 700: 0.0669,
800: 0.0567, 900: 0.0608, 1000: 0.0721, 1100: 0.0731, 1200: 0.0706`.
Best at step 200; late training oscillates within ~0.04–0.07. There is no
early-stopping/checkpoint-selection step: the final weights are what was
measured (honesty note 5).

| Statistic | Value |

### 5.3 Surprise / residual separation

Surprise is the per-transition mean squared latent prediction error,
`mean_d (z_hat_{t+1,d} - z_{t+1,d})²`; it is measured with the encoder frozen.
Residual quantiles over all 384 eval transitions per regime:

| Regime | Mean | Median | q90 | q95 | q99 | Max | Std |
| --- | --- | --- | --- | --- | --- | --- | --- |
| In-distribution (normal) | 0.04939 | 0.02429 | 0.10263 | 0.17219 | 0.41304 | 0.78362 | 0.08125 |
| Identity residual (normal) | 0.28262 | 0.24352 | 0.57687 | 0.68426 | 0.88559 | 0.94197 | 0.21162 |
| Whole-episode flipped | 0.25527 | 0.18360 | 0.59335 | 0.77073 | 1.11765 | 1.71326 | 0.25440 |
| Mid-episode flip, pre-flip (steps 0–7) | 0.08396 | 0.04060 | 0.22385 | 0.30897 | 0.63465 | 0.78362 | 0.12498 |
| Mid-episode flip, post-flip (steps 8–23) | 0.28597 | 0.21629 | 0.61388 | 0.71058 | 1.02408 | 1.41609 | 0.23526 |

Phase-matched comparison matters: normal evaluation includes a cold-start

post-flip transitions is the *same transition indices* on the unflipped twin
(`0.03210` mean). Separation:

| Comparison | Ratio |
| --- | --- |

Per-step mean surprise (average over 16 episodes), grouped to keep the table
compact:

| Transition indices | Normal | Mid-flip | Ratio |
| --- | --- | --- | --- |
| 0–7 (pre-flip / cold start) | 0.0839 | 0.0839 (identical twin) | 1.00× |
| 8–11 (first 4 affected) | 0.0346 | 0.3467 | 10.03× |

The per-step curve shows the expected shape: the first affected prediction

spike peaks one step later at `0.490` (normal `0.036`), then remains 6–10×
the normal level through the end of the 24-step episode. With weights frozen,
the GRU's hidden state can partially track the new acceleration but cannot
identify the new law; this is exactly the signal phase 5 uses, and the
predictor adaptation is out of scope here.

## 6. What phases 4–5 can consume

* `PhysicsEnv` gives a genuine law flip: `flip_gravity()` changes trajectories
  only; the observation distribution is identical by construction.
* The frozen encoder gives deterministic latents for digest clustering;
  `encoder_parameters()`/`predictor_parameters()` and `predictor_optimizer()`
  give the overlay path a predictor-only adaptation surface.
* The phase-5 acceptance signal is measured: post-flip surprise rises to
  ≈8.9–10× the phase-matched baseline, with a one-step-delayed peak. A digest
  overlay triggered on that spike can then adapt the predictor while the
  encoder stays frozen; flipping back should make the overlay stale (not
  measured here — that is phase 5).
* `MicroLeWM.save/load` round-trips in a fresh interpreter with the frozen
  flag, config, and metadata intact.

## 8. Honesty notes (measured vs. assumed)

1. **A false start left stale files, now removed.** An initial `nohup`
   background launch died with the shell and produced an empty
   `.work/forge/train_default.log` plus a stray `train.pid`; the reported run
   was executed as a managed background job, and `stats.json` is the record of
   that run. Those stale files (and a smoke artifact directory and prototype
   script) were deleted; `.work/forge` contains only `checkpoint.pt` and
   `stats.json`.
2. **Wall time is contended-host wall time.** 235.4 s training / 237.9 s total
   was measured while the host load average was ≈16 from concurrent teammate
   jobs. The per-step cost (196.2 ms) is the number to extrapolate; it is not a
   best-case single-tenant benchmark.
3. **These are our numbers, not the paper's.** No attempt is made to reproduce
   LeWM's PushT VoE results; the model is a ~0.52 M-parameter CPU study trained
   on our own world. The post-flip separation (5.79× all-normal, 8.91×
   phase-matched, 10.03× immediate) is measured on 384 held-out transitions per
   regime, not on the paper protocol.
4. **The normal baseline includes cold-start steps.** The GRU starts each
   episode with a zero hidden state, so normal steps 0–1 have high surprise
   (0.221, 0.105). The headline 5.79× uses all normal transitions; the fair
   phase-matched comparison is 8.91×. Both are reported rather than choosing
   the flattering one.
5. **No checkpoint selection.** The reported metrics use the final weights
   after 1200 steps, not the best validation point (best was step 200 at
   0.0419). This makes the phase-5 baseline slightly worse than a
   best-checkpoint baseline would be; it was kept simple and reproducible.
6. **SIGReg is near-Gaussian, not exactly Gaussian.** Final SIGReg is 1.457
   versus 1.105 for iid N(0,1) at this configuration; per-dimension latent std
   ranges 0.58–1.17. There is no collapse (64/64 dims std > 0.25), but the
   latents are not perfectly isotropic, and SIGReg is computed on 24×13
   samples per step with 256 projections (the reference uses batches of 128
   and 1024 projections).
7. **Prediction MSE is not comparable across encoder updates.** The training
   loss starts at ~1.6e-6 because the zero-init head copies `z_t` and the
   initial encoder nearly ignores motion. The meaningful comparison is against
   the identity baseline at the final encoder: 0.048 vs 0.229 on a fixed
   validation window (4.77× lower).
8. **The phase-matched eval windows overlap the normal eval windows** (same
   seeds, same actions); they are the correct control for a causal flip claim,
   but they are not statistically independent episodes. The whole-episode
   flipped set uses the same seeds too, which also makes it a paired
   comparison rather than a fresh sample.
9. **The world is simplified by design.** No body-body collisions, no friction,
   no object actuation, no termination, restitution 0.90 and a speed cap. These
   are stated choices for a controlled boundary slice, not claims about
   physical realism.
10. **The flip is only the sign.** Magnitude, restitution, and thrust are fixed;
    `flip_gravity()` toggles the sign and counts flips. Phase 5 may want
    magnitude changes, which this API does not expose yet.
11. **Test redesign, stated explicitly.** The overfit test originally used a
    4-window batch and a 32-projection tiny model; in that regime SIGReg's
    gradient at initialization is ≈1e-4 and the prediction-collapse force wins,
    so the loss moved by <0.2% in 60 steps (a pathological probe, not a working
    overfit check). It now uses the default-size micro-LeWM at 64×64, 8 windows
    of length 8, 80 steps, and requires a 50% loss drop (stricter than the
    original 30% threshold) plus latent spread. The checkpoint round-trip test
    compares configs via `MicroLeWMConfig.from_dict` because JSON turns the
    `encoder_widths` tuple into a list; the comparison is still exact.
12. **The mixed-gravity control was not run.** `--train-gravity mixed` is
    implemented but unreported: the headline protocol is normal-only training
    because that is the only way to have an in-distribution vs flipped split.
13. **Reproducibility is approximate at the 1e-8 level, not bitwise.** Fixed
    seed and 8 threads reproduce the eval surprise means to ~7e-9 in a clean
    process (verified: normal 0.049386311 vs stats 0.049386318; post-flip
    0.285973042 vs 0.285973035). CPU reduction order across thread counts can
    change the last bits; the environment itself is exactly deterministic for a
    fixed seed/action stream.
14. **`fit` freezes the encoder at the end, but the CLI checkpoint is the final
    weights.** If phase 5 needs to start from an unfrozen encoder, it must use
    `--train-gravity`/another fit; `unfreeze_encoder()` exists but is
    experimental-only and is not used in the measured path.
